# Автобус на заказ: сервис заказных перевозок «По пути»

## О проекте
Сервис заказных перевозок «По пути» (Мосгортранс) — это гибрид маршрутки и такси в Новой Москве. Пассажир указывает точки А и Б, а алгоритм строит динамический маршрут, подсаживая попутчиков. 

**Основная проблема:** сервис заказных перевозок «По пути» строит маршруты только в реальном времени — система на ходу подбирает автобус и добавляет попутные заезды. Из-за этого время в пути становится непредсказуемым, а в часы пик количество свободных машин сокращается. Механизма предзаказа при этом нет, поэтому пассажир не может спланировать поездку заранее, а перевозчик не может рассчитывать на гарантированную загрузку.

**Наша задача:** понять, что нужно сделать для того, чтобы пассажиры смогли пользоваться *услугой предварительного заказа*, перевозчик — обслуживать *гарантированный объём пассажиропотока*

---

## Цели и задачи

### Для пассажира:
- Предзаказ поездки за несколько часов.
- Гарантированное место и понятное время поездки.
- Прозрачные правила оплаты, отмены и возврата.
- Предсказуемый маршрут и время в пути.

### Для перевозчика:
- Прогнозируемый спрос и загрузка транспорта.
- Учитывание предзаказов при планировании рейсов.
- Снижение недозагруженных и холостых пробегов.
- Эффективное объединение заказов.

### Для сервиса:
- Определить пользовательский сценарий предзаказа.
- Разработать правила бронирования, оплаты и отмены.
- Определить принципы формирования рейсов.
- Определить показатели эффективности предзаказа.

## Backend - серверная часть
Backend реализован на Python с использованием FastAPI, SQLAlchemy и PostgreSQL.
Серверная часть отвечает за обработку запросов, управление бронированиями, хранение информации о рейсах и платежах, а также взаимодействие с алгоритмами проекта.

### Реализованные функции:
- Создание предварительного бронирования поездки.
- Проверка существования рейса.
- Проверка доступности мест на рейсе.
- Атомарное резервирование мест при создании заказа.
- Защита от одновременного бронирования последнего свободного места.
- Получение информации о бронировании по идентификатору.
- Получение списка бронирований пользователя.
- Имитация оплаты с сохранением статуса платежа.
- Отмена бронирования с возвратом места в число доступных.
- Получение списка бронирований пользователя.
- Создание платежа.
- Хранение информации о бронированиях, рейсах и платежах в PostgreSQL.

### API

Основные реализованные endpoints:

|Метод|Endpoint|Назначение|
|---|---|---|
|`POST`|`/api/v1/trips`|Создание рейса.|
|`GET`|`/api/v1/trips/{trip_id}`|Получение информации о рейсе.|
|`POST`|`/api/v1/preorders`|Создание предварительного бронирования.|
|`GET`|`/api/v1/preorders/{preorder_id}`|Получение информации о бронировании.|
|`POST`|`/api/v1/preorders/{preorder_id}/pay`|Упрощённая имитация оплаты.|
|`POST`|`/api/v1/preorders/{preorder_id}/cancel`|Отмена бронирования.|
|`GET`|`/api/v1/my/preorders`|Получение бронирований пользователя.|
|`POST`|`/api/v1/payments`|Создание платежа.|
|`GET`|`/api/v1/payments/{payment_id}`|Получение информации о платеже.|
|`POST`|`/api/v1/payments/{payment_id}/confirm`|Подтверждение платежа.|
|`POST`|`/api/v1/payments/{payment_id}/fail`|Фиксация ошибки оплаты.|

Планируемые endpoints:

| Метод  | Endpoint                   | Назначение                                           |
| ------ | -------------------------- | ---------------------------------------------------- |
| `GET`  | `/api/v1/trips`            | Получение списка доступных рейсов.                   |
| `GET`  | `/api/v1/stops`            | Получение списка остановок.                          |
| `GET`  | `/api/v1/stops/{id}`       | Получение информации об остановке.                   |
| `POST` | `/api/v1/preorders/search` | Поиск подходящих поездок по параметрам пользователя. |

### Запуск backend
1. Перейти в папку `backend/`. 
2. Установить зависимости:
    ```PowerShell
    pip install -r requirements.txt
    ``` 
3. Создать файл `.env` на основе `.env.example` и указать параметры подключения к собственной базе данных PostgreSQL.
4. Запустить сервер:
    ```PowerShell
    python -m uvicorn app.main:app --reload
    ```
5. Открыть документацию API в браузере:
    [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

**Важно:** файл `.env` содержит локальные настройки и пароли, поэтому не должен добавляться в репозиторий. В Git хранится только пример `.env.example`.
