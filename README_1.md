## 💡 О проекте

«**По пути**» — существующий сервис перевозок по требованию: пассажир выбирает остановки отправления и назначения, а транспорт подбирается с учётом других заказов и возможных попутных заездов.

**Идея нашего учебного проекта** — дополнить такой сценарий **предварительным заказом поездки**, чтобы пассажиры могли планировать поездки, а перевозчик — заранее оценивать спрос и загрузку машин.

> **Ключевой принцип:** основной режим «Поехать сейчас» работает по логике заказа такси, **без выбора рейсов из расписания**. Дата и время появляются только в режиме «Запланировать».

| Проблема | Что предлагаем |
|:--|:--|
| Непредсказуемое время подачи и прибытия | Понятный статус заказа и расчётные параметры поездки |
| Нельзя заранее запланировать поездку | Предзаказ с выбором даты и времени |
| Неясная загрузка транспорта в часы пик | Учёт предзаказов при планировании и группировке |
| Сложно планировать количество машин | Прогнозируемый спрос и более эффективное назначение транспорта |

### Для кого разрабатываем

- **Пассажир:** удобный поиск, предзаказ, известная стоимость и понятные правила отмены.
- **Перевозчик:** информация о будущем спросе, загрузке и распределении транспорта.
- **Система:** объединение совместимых заявок, подбор рейсов и контроль доступных мест.

## ✨ Пользовательские сценарии

### ⚡ Поехать сейчас

**Сценарий без расписания:** `А → Б → пассажиры → поиск транспорта → предложение поездки`.

Пользователь выбирает остановки и количество пассажиров. Система должна найти подходящий микроавтобус и показать время подачи, длительность поездки и цену — **без ручного выбора времени отправления**.

### 🗓️ Запланировать

**Сценарий предзаказа:** `А → Б → дата и время → пассажиры → проверка возможности заказа`.

Дата и время нужны только в этом режиме. В текущем frontend действуют проверки: **от 30 минут до 48 часов** и шаг времени **10 минут**. Эти правила требуют окончательного согласования с серверной частью.

### Текущее состояние проекта

| Часть системы | Состояние | Комментарий |
|:--|:--:|:--|
| React-приложение и маршрутизация | ✅ | Главная, поиск и заглушка «Мои поездки» |
| Дизайн и мобильная версия | ✅ | Фирменные цвета, компоненты, адаптивная форма |
| Интерактивная карта | ✅ | MapLibre + OpenFreeMap, переключение областей просмотра |

| Состояния поиска | 🧪 | Загрузка, найдено, нет транспорта, ошибка — **демонстрация** |
| `frontend/src/api/trips.ts` | 🟡 | Подготовлен клиент для будущего API, без реальной интеграции |
| Выбор остановок из справочника | ⏳ | Ожидается интеграция с компонентами и данными остановок |

**Обозначения:** ✅ реализовано в frontend · 🧪 демонстрационные данные · 🟡 подготовлено частично · ⏳ предстоит.

> [!IMPORTANT]
> Сейчас это **учебный прототип**, а не действующий сервис заказа микроавтобусов. Показанные в интерфейсе время подачи, стоимость и свободные места не являются реальными предложениями транспорта.

## 🏗️ Архитектура

```text
Пользователь
    │
    ▼
Frontend — React + TypeScript + Vite
    │  ├─ главная страница и поиск
    │  ├─ карта MapLibre
    │  └─ состояния и карточка поездки
    │
    │ REST API  [интеграция в разработке]
    ▼
Backend — FastAPI + SQLAlchemy
    │  ├─ рейсы и остановки
    │  ├─ бронирования и платежи
    │  └─ проверка доступных мест
    │
    ├───────────────► PostgreSQL
    │
    └───────────────► Алгоритмы
                       ├─ группировка заказов
                       ├─ назначение транспорта
                       └─ правила возврата
```

### Технологии

| Уровень | Стек | Назначение |
|:--|:--|:--|
| **Frontend** | React, TypeScript, Vite | Интерфейс заказа и поиск поездок |
| **Навигация** | React Router | Переходы между страницами |

| **Данные** | PostgreSQL, SQLAlchemy | Рейсы, заказы, пассажиры и платежи |
| **Алгоритмы** | Python | Группировка заказов и распределение машин |
| **Тестирование** | pytest, ESLint, TypeScript | Проверки серверной и клиентской частей |

## 🚀 Быстрый запуск

### Frontend

**Нужны:** Node.js и npm.

```bash
git clone https://github.com/victoriapetrova2910/Project_custombus.git
cd Project_custombus/frontend
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно **http://localhost:5173/**).

```bash
npm run build   # Проверка TypeScript и production-сборка
npm run lint    # Проверка ESLint
```

Frontend можно запустить **без backend**: сценарий поиска будет работать в демонстрационном режиме.

📖 Подробности: [frontend/README.md](frontend/README.md).

### Backend

**Нужны:** Python, PostgreSQL и локальные настройки подключения к БД.

Из корня репозитория:

```bash
cd backend
pip install -r requirements.txt
# Создайте .env по образцу .env.example и настройте PostgreSQL
python -m uvicorn app.main:app --reload
```

Документация API при запущенном сервере: **http://127.0.0.1:8000/docs**.

> [!NOTE]
> Это краткая инструкция, а не гарантия запуска текущей серверной ветки «из коробки»: согласованность импортов, моделей, миграций и подключения к БД ещё требует интеграционной проверки. Файлы с паролями (`.env`, `.env.local`) не следует добавлять в Git.

## ⚙️ Серверная часть и алгоритмы

### API и бронирования

В кодовой базе предусмотрены операции с рейсами, предварительными заказами и платежами. В частности, реализовывались проверка мест и атомарное резервирование, получение и отмена бронирования, имитация оплаты. **Наличие обработчиков в коде не означает, что весь процесс уже протестирован совместно с frontend.**

**Описанные в проекте эндпоинты:**

| Метод | Путь | Назначение |
|:--:|:--|:--|
| `POST` | `/api/v1/trips` | Создание рейса |
| `GET` | `/api/v1/trips/{trip_id}` | Получение рейса |
| `POST` | `/api/v1/preorders` | Создание предзаказа |
| `GET` | `/api/v1/preorders/{preorder_id}` | Получение предзаказа |
| `POST` | `/api/v1/preorders/{preorder_id}/pay` | Демонстрационная оплата |
| `POST` | `/api/v1/preorders/{preorder_id}/cancel` | Отмена бронирования |
| `GET` | `/api/v1/my/preorders` | Предзаказы пользователя |
| `POST` | `/api/v1/payments` | Создание платежа |
| `GET` | `/api/v1/payments/{payment_id}` | Статус платежа |
| `POST` | `/api/v1/payments/{payment_id}/confirm` | Подтверждение платежа |
| `POST` | `/api/v1/payments/{payment_id}/fail` | Фиксация ошибки оплаты |

**Планируемые / ожидающие интеграции API:**

| Метод | Путь | Назначение |
|:--:|:--|:--|
| `GET` | `/api/v1/trips` | Поиск или список подходящих рейсов |
| `GET` | `/api/v1/stops` | Справочник остановок |
| `GET` | `/api/v1/stops/{id}` | Информация об остановке |
| `POST` | `/api/v1/preorders/search` | Поиск поездок для предзаказа |

> [!WARNING]
> Путь `/api/v1/preorders/search` указан как **планируемый контракт**. Frontend пока не отправляет на него рабочие запросы. Отдельная логика нужна и для режима **«Поехать сейчас»**.

### Алгоритмы

| Модуль | Подход | Учитываемые ограничения |
|:--|:--|:--|
| `grouping.py` | Жадная группировка совместимых заказов | Вместимость; окно посадки **15 мин**; расстояние до **500 м**; угол направления до **45°**; коэффициент удлинения до **1,5** |
| `scheduling.py` | Best Fit для назначения машин | Вместимость, занятость, интервалы рейсов, буфер **15 мин** |
| `refund.py` | Расчёт возврата при отмене | Доля возврата, время отмены, округление суммы |

Параметры алгоритмов и правила возврата — **текущие настройки реализации**. Их необходимо сверить с согласованными бизнес-правилами. Полная связка алгоритмов с API ещё требует проверки.

### Данные и тесты

В PostgreSQL предусмотрены основные сущности `trips`, `preorders`, `payments` и связанные модели. Для настройки используются скрипты `backend/init_db.py` и `backend/check_db.py` (при наличии и корректной конфигурации БД).

В репозитории предусмотрены тесты группировки, назначения транспорта, возвратов и конкурентного бронирования.

```bash
cd backend
pytest
```

Отдельные интеграционные проверки требуют работающего backend и подготовленной PostgreSQL.
